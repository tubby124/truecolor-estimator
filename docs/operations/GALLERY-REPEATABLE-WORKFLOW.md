September 9, 2026. Coroplast, postcards and retractable banners are now distinct tested examples of the same scoped display binding. The six second-batch assets reused existing generated sources; no regeneration or shared component rewrite was necessary. These lessons guide future work, not blanket approval of all 124 slots.

## Minimum repeatable evidence

1. Fix exact product/asset selection and independent acceptance examples first. Preserve exclusions and byte-level provenance limitations. Map changed display data versus unchanged shared consumers.
2. Add narrow data bindings and product-specific contracts. Preserve existing gallery keyboard/lightbox and image-sitemap deny contracts. Do not reimplement a working component for each product.
3. Run records, relevant tests and required application/CI gates under current policy. Reuse the existing semantic/visual/performance helpers and production-build artifacts for the unchanged candidate. Capture before/after under the same isolation, viewport, cache and metric policy. A materially changed candidate invalidates affected evidence; unchanged files do not need repeated inspection merely because the branch name changed.
4. Inspect all selected images and gallery/lightbox layouts at mobile/tablet/desktop, including tall aspect ratios. Check exact delivery hashes, alt, sizes, reserved dimensions, optimizer decoding/cache, initial image bytes, LCP and CLS. Performance evidence must retain five cold plus one warm runs per product/mobile-desktop where required by the active release plan. Do not turn a single warm result into a performance claim.
5. Required PR checks → merge → correct main **push lint-test** → Railway exact commit SUCCESS → public readback. Filter workflow name/event and commit: an unrelated scheduled `Order Reply Sync` success on the same SHA is not release CI. A successful build alone is not deployment.
6. Save a sanitized receipt and current-state update; keep private raw evidence with the task. Preserve original files for a narrow rollback. Record ranking/attribution limitations and observe actual results without inventing causal lift.

## Time saved and remaining bottleneck

Asset reuse, existing component reuse, bounded consumer checks and one batch PR remove repeated generation/discovery. Two legacy waiting assumptions were fragile: rotating homepage network-idle, and live banner visual network-idle. Semantic homepage checks use bounded DOM/H1 readiness consistently before and after; visual checks can use visible gallery plus exact selected-image decode. This does not change lab timing protocols or excuse a missing resource.

Current workflow runs full application checks locally, on the PR and on main; these builds are a major delay, independently of model choice. Documentation-only closeout uses the dependency-free records check locally, but current required PR CI still applies. A future separately reviewed change may add a trusted docs-only path or reuse build artifacts across gates. Do not skip required checks, disable Wait for CI, or use a skip token as an ad hoc speed fix.
