## Product behavior

- `/staff/social/settings` reports actual Google connection health, configuration/authorization/access failures and the verified target. Paginated discovery matches normalized title AND complete postal address and rejects ambiguous locations. No listing is created. Business OAuth state binds both user and business; token encryption uses AES-GCM with business ID as authenticated data.
- The same settings screen imports actual paginated Google local posts into separate `social_gbp_history` records. Each page saves provider IDs, type, dates, media, status and read time, then advances a durable cursor. Closing the browser preserves progress. Import is bounded to 25 pages per UI session with explicit resume; repeated tokens cannot create an endless browser loop. The newest20 offers (or all if fewer) can be reviewed separately from other posts. Reading history does not queue content.
- Google discontinued local-post insights and the `LOCAL_POST_VIEWS_SEARCH`/`LOCAL_POST_ACTIONS_CALL_TO_ACTION` metrics on February20,2023, with no replacement. The old REST page remains online. Imported offers explicitly show unavailable metrics; unavailable is never represented as zero or evidence of poor performance. No removed insights endpoint is called. [Official sunset dates](https://developers.google.com/my-business/content/sunset-dates?authuser=0&hl=en).
- Google publication uses the existing Business Profile localPosts API with a `PHOTO` media item. `STANDARD` handles ordinary non-expiring promotion. `OFFER` requires a persisted source-bound shared offer with real dates, event title and redemption URL/terms; generic callToAction is not sent for offers. Google's returned LIVE/PROCESSING/REJECTED states are distinguished. Unknown or pending creation stays held with its provider ID; no automatic create retry occurs. [Local posts reference](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.localPosts), [media contract](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.media#MediaItem).
- `/staff/social/offers` prepares immutable catalogue-backed shared offers. Select an existing purchasable product and cleared uploaded JPEG; optional real dates select an offer period. A deterministic Sharp/SVG template prints the source-derived configured standalone pre-tax order total and minimum disclosure. No AI paints or calculates price figures. Numeric/discount claims cannot be introduced through free-form terms. Ordinary price-bearing promotions do not invent savings or expiry.
- Shared offers open in Compose with channel copy, exact media, product/configuration/fingerprint and Google payload attached. Compose creates separate destination drafts. Each still requires exact rights/media/account/copy/schedule approval. Google copy excludes a feed URL/hashtags and uses the action/redemption field. The staff can prepare a new shared offer when terms/copy change; edited shared-offer text is held until it matches a newly prepared source-bound offer.
- `/staff/social/monthly` supports 31 logical creatives, stable resumable generation IDs, chunked durable draft creation, monthly lists and paginated exact review. Google is deliberately selected per appropriate creative; daily IG/FB showcase cadence does not imply daily Google publishing. See [monthly scheduler details](MONTHLY-REVIEW-SCHEDULER-20260906.md).

## Business isolation and feature activation

`requireSocialBusiness(req?)` always runs server-side staff authorization. Before migration, only the existing owner/default True Color context is permitted and legacy SQL remains unchanged. After `SOCIAL_BUSINESS_SCOPING_ENABLED=true`, **every** context including the omitted/default ID requires an operator membership and active business. A synthetic B operator cannot inherit True Color by omitting the header. The optional `X-Social-Business-Id` is checked against membership, never trusted from a draft body. There is no new public client portal.

Default business ID: `00000000-0000-4000-8000-000000000001`. New tables/rows use business_id. Parent/child composite FKs prevent cross-business campaigns, offers, batches, receipts and generation jobs. The migration replaces old single-column campaign/receipt FKs so PostgREST embeds remain unambiguous. Browser direct social table grants/policies are removed; existing calendars/queues use authenticated 15-second visible-tab API polling. Legacy True Color-only Blitz endpoints explicitly deny other business contexts.

True Color keeps its protected Meta environment configuration to preserve current approvals. Other businesses use encrypted `social_channel_credentials` with `SOCIAL_CREDENTIAL_ENCRYPTION_KEY` (64 hex characters) and business-bound AES-GCM. Google uses separate business-bound encrypted credentials. Never copy global provider tokens into another business. No settings UI returns a token. Actual second-business catalogue/profile generation and price offers remain blocked until explicitly onboarded; P's True Color catalogue is not treated as another client's facts.

True Color's original cleared social URLs remain `social/<year>/<uuid>.jpg`. Other businesses use `businesses/<business-id>/social/<year>/<uuid>.jpg`. Private catalogue/original access validates the authorized business and prefix before signing. Restrictive storage policies deny browser enumeration of social-images/social-library; service API access remains scoped. Cleared public derivative URLs intentionally remain downloadable by providers. Production storage policy/public URL readback is required during activation; no private originals are made public.
