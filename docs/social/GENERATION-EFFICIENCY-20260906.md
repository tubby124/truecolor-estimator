## Result and interfaces

`POST /api/staff/social/captions` accepts a stable UUID `requestId`, `selectedChannels` from `instagram`, `facebook`, `gbp`, optional `productSlug`/`configuration`, `includePrice`, `caption_raw`, `topic`, `campaign_slug`, `angle`, and compressed `image_base64`/`image_type`. Schedule fields are not semantic inputs. Browser helper: `generateCaptions(input, businessId?)` in `src/lib/social/generation-client.ts`. It never retries or invents a replacement ID after a transport error. `readGeneration(requestId,businessId?)` reads durable state. Preserve the response's original `jobId` when a concurrent identical request resolves to another existing job.

Response: `drafts` is a partial selected-channel map, `facts` is the pricing lane's exact `ProductFacts` or null, `status` is completed/partial/running/failed/held, plus `jobId`, `cacheHit`, actual invocation `usage`, observation, hashtag evidence and errors. The explicit legacy flat fields include Instagram/Facebook/GBP and `twitter: ''`; no X provider generation occurs. Missing/failed channels remain editable drafts and must not be auto-approved. Successful saved job usage remains available through GET; cache/replay invocation reports zero new calls and zero new cost.

The resolver is P's server-only `resolveProductFacts({productSlug,configuration})`, with the configured quantity, raw subtotal, standalone pretax total, minimum disclosure and source fingerprint. No second production price table exists. Model prose cannot supply a price. `priceDisclosure(facts)` appends the exact verified configuration and minimum block. `validateBoundCaption(caption,channel,facts)` rechecks final edited generated copy; G must call this during save/approval/publish and bind `product_slug`, `product_configuration`, `fact_fingerprint`, `generation_job_id`. A current fingerprint with an edited wrong price is rejected. G also verifies that the same-business generation job has that destination among its successful drafts. Changing a quote/order is outside this lane.

## Prompt, observations and cache

The fixed model remains `anthropic/claude-sonnet-4-6`. The prompt contains compact shop voice, selected product identity, campaign/angle, at most four shortened recent captions, reusable hashtag candidates and an optional photo. It does not send the historical full catalogue, hardcoded price promises, competitor claims or unrequested channel prompts. Showcase prices are optional. Commercial/numeric prose, unsupported delivery/warranty/discount claims, invented client stories, schema violations and platform limits are checked deterministically. The guard is conservative; it is not proof that arbitrary natural-language claims are universally true. Owner review remains required.

The first photo request observes the photo and drafts copy in one call. Existing browser compression remains at 1024px. The server hashes actual compressed bytes; it never fetches an arbitrary submitted URL. A cached unreadable observation blocks generation for those same bytes. A clearer image is a different hash. Text-only copy never replaces an existing photo observation.

Cache identity binds business UUID, media bytes, selected channels, product source fingerprint, configuration, caption/topic/campaign/angle, includePrice, profile version, prompt version and model. Channel order and object key order are canonicalized. A schedule-only change preserves cache identity. A changed item affects only that item's identity. Changed catalogue facts invalidate copy, while the independently keyed observation remains reusable. Exact completed cache reads make zero AI calls and are available even at an exhausted budget. Full-result cache TTL is 30 days. Prompt/profile recipe changes must bump `PROMPT_VERSION`/`PROFILE_VERSION`.

## Jobs, concurrency and recovery

`migrations/20260906_social_generation.sql` creates service-only generation settings, daily usage, jobs, cache, observations and dated hashtag candidates. Business IDs and request UUIDs form a composite identity. Per-business row locks serialize claim/settlement; max two jobs run per business. Concurrent different request IDs with identical running or held content return the original job, without another reservation. Same ID with changed input/facts returns409. Five-minute abandoned leases become held and retain reservations; a successful provider response cannot safely be inferred after a process dies.

Only explicit provider HTTP429 can retry automatically, once. Each request reserves at most two calls and falls back to one when only one fits; execution honors the actual allocation. HTTP408, gateway/server failures and transport/response-read timeouts are held, with no automatic replay. Other failures/invalid JSON are terminal, with no repair loop. Persisted partial results can be explicitly resumed using a fresh UUID plus `resumeJobId`; only missing channels are requested. Exact same-ID replay returns its saved status. Successful channels remain unchanged. A held request cannot use partial-resume. Reconciliation is deliberate operator work: inspect the saved provider request ID/usage and OpenRouter activity before clearing a hold or authorizing new work; never relabel an uncertain request as uncharged without provider evidence.

The rewriter keeps request identity in browser session storage using an input hash, exposes partial-resume and an explicit fresh request after a confirmed409 stale-facts conflict, and keeps editable output on failure. Network/persistence uncertainty retains the same request ID. After a server settlement error, use GET/same-ID replay and inspect durable state before another paid action. The monthly UI's persisted IDs are owned by G.

## Usage and owner controls

`GET/PATCH /api/staff/social/generation/settings` and `GenerationUsageSettings` expose daily call limits and used/reserved calls, available provider cost and reserved USD. UTC is the accounting day. True Color is seeded at20 calls/day as an editable implementation default preserving staff on-demand use; it is not a measured or newly approved paid-test budget. New businesses default to0. Unused retry reservations are released on known terminal settlement. Definitively zero-call failures have zero cost; unknown billed outcomes retain reservations. No automatic batch starts when limits change.

The optional daily USD threshold uses an owner-configured per-call reservation. This is conservative admission accounting, not a provider-enforced price cap: actual provider billing can exceed that estimate. Configure an OpenRouter account/key hard limit for a hard spending boundary. If the USD threshold is set without a reservation, dispatch is refused. Missing usage remains null, never an invented measured cost. No cost-per-post savings or successful live generation is claimed from mocked tests.

OpenRouter usage is read from each actual response without an extra model request: model/provider ID, prompt/completion tokens and reported `usage.cost`. See [OpenRouter usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting). Unknown costs preserve the reservation. No provider switch, paid enhancement integration, prepaid commitment or automatic top-up was added.

## Hashtag evidence

`POST /api/staff/social/generation/hashtags` accepts a staff-authenticated monthly/on-demand research package: `productSlug`, `candidates` hashtag array, HTTPS `sources` and `researchedAt` within the past31 days. Its31-day expiry is fixed from the research date. This route stores evidence and makes no paid research call. Caption preparation reads the latest nonexpired same-business/product research once from storage. Absent research uses clearly labelled generic local suggestions; historical static campaign templates are not represented as dated research. Do research once per month or when specifically requested, save the package, and reuse it across posts.
